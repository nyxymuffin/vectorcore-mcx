# VectorCore MCX — Codebase Audit

**Date:** 2026-08-11
**Scope:** Full-tree audit of `mcxas` (Go MCX/MCPTT IMS Application Server), with a
specific eye toward readiness for adding a **P25 ISSI interface (TIA-102.BACA family)**.
**Method:** Static inspection of all Go sources, tests, config, build, and packaging.
The Go toolchain is not installed on this machine, so nothing was compiled or run;
findings are by code reading, not by test execution.

---

## 1. Verdict

The project is a **functional single-vendor MCPTT lab prototype**, not a platform. It
does real work — hand-rolled SIP, XCAP/CMS document generation, RTP relay, and a
partial TS 24.380 floor-control implementation all exist and are wired together — but
it is coupled end-to-end to a single set of MCPTT assumptions, has **no authentication
anywhere in any interface**, and has **no transaction, transport, or peer abstraction**
to hang a second protocol off of.

**Readiness to start a P25 ISSI interface: not yet.** ISSI can share the low-level SIP
parser and the opaque-payload RTP relay, but every layer above those is hardwired to
MCPTT (dispatch, identity model, content types, SDP generation, floor protocol, single
global media port, registration gating). Attempting ISSI on top of the code as it
stands means threading `if isISSI(...)` branches through every handler in a 2,700-line
SIP file and a 650-line media file. The honest sequence is: **(a) fix the security
floor, (b) extract a peer/profile abstraction and a transaction boundary, then (c) add
ISSI as a profile.** Details and a recommended seam are in §6.

The README already says "work in progress; a fully working implementation should not be
expected yet," which is accurate.

---

## 2. What actually works

This is not a skeleton. The following are implemented and have at least happy-path test
coverage:

- **SIP signaling** (`internal/sip/sip.go`, 2709 lines): hand-written parser, UDP + TCP
  listeners, OPTIONS, PUBLISH (poc-settings + presence affiliation), third-party
  REGISTER with expiry, SUBSCRIBE + initial NOTIFY, full INVITE/ACK/BYE/CANCEL, in-dialog
  UPDATE/INFO, multipart MCPTT-info + SDP extraction, Record-Route/Contact construction,
  and group-call fan-out to other registered members.
- **CMS/XCAP + identity** (`internal/cms/server.go`, 1063 lines): XCAP GET/PUT/DELETE,
  generated Rel-13 UE-init-config, UE-config, MCPTT user profile, service config, and
  OMA group documents, with SHA-1 ETags and xcap-diff notifications. Plus a development
  IdMS OAuth shim.
- **Media** (`internal/media/observer.go`, 647 lines): RTP/RTCP/floor UDP listeners,
  RTP header parsing, per-call stats accounting (packets, loss, jitter, bytes), RTP relay
  between legs of a group call, and TS 24.380-shaped floor request/grant/deny/release/idle
  handling with single-holder enforcement.
- **Persistence** (`internal/store`): SQLite and Postgres behind one interface, covering
  users, groups, memberships, affiliations, CMS docs, publications, subscriptions,
  dialogs, registrations, and calls.
- **OAM** (`internal/api`): huma-generated REST API + OpenAPI doc, Prometheus metrics,
  health check, and an embedded React SPA.

The build (`Makefile`) and packaging (`systemd` unit, `make install`) are complete and
coherent.

## 3. Critical issues (fix before ISSI, before any non-lab exposure)

These are ranked. The security items are not theoretical — each is reachable by any host
that can send a packet to the listener.

### 3.1 No authentication on any interface
- **SIP** (`sip.go`): no `Authorization`/`WWW-Authenticate`, no digest, no 401/407 ever
  emitted, no source-IP ACL. `handleRegister` (sip.go:393) takes the served identity
  straight from the `To` header — **any host can register or de-register any subscriber**
  (`Contact: *`, `Expires: 0`). `identityFrom` (sip.go:2335) trusts client-settable
  `P-Preferred-Identity`, and that identity drives affiliation writes, XCAP disclosure,
  and group-call admission.
- **XCAP/CMS** (`cms/server.go:33`): bare `ServeMux`, no auth, no TLS. Anyone reaching
  `:8100` can read every user profile and group roster and PUT/DELETE arbitrary documents.
- **OAM REST API** (`api/server.go:32`): three middlewares (Recoverer, RealIP, logger),
  **no auth, no TLS, no API key**. `POST/PUT/DELETE /api/v1/users|groups|memberships`
  are world-open, as is `/metrics` and the live registration/call surveillance views.
- **Media** (`observer.go:262`): the RTP relay is an unauthenticated UDP fan-out
  reflector; the only gate (`rtpAuthorizedForFloor`, observer.go:444) returns true
  whenever no floor holder is set.

### 3.2 IdMS shim is a total auth bypass, always on
`api/idms.go` issues **unsigned (`alg:none`) JWTs** (idms.go:135) asserting a real
provisioned subscriber's MCPTT identity, ignoring `code`, `grant_type`, and any client
secret (idms.go:58-97). The fallback hands out **the first enabled user's identity** to a
caller it cannot identify (idms.go:114-127). `/idms/authorize` is an **open redirect**
with unescaped `state` injection (idms.go:29-37). There is **no config flag to disable
it** (unlike `cms.enabled`/`media.enabled`) — it is always registered, and the generated
UE-init-config advertises it to every client over plain HTTP. In an MCX context the
forged `mcptt_id` is the identity used for floor priority and emergency-call
authorization.

### 3.3 No TLS / no encryption anywhere
No `crypto/tls` import in the tree; no cert/key fields in config. SIP, XCAP, OAM, and the
IdMS token exchange are all plaintext. This directly violates the standing rule that all
network connections be encrypted and authenticated. `config.yaml:32` even ships a Postgres
DSN with `sslmode=disable`.

### 3.4 SIP has no transaction layer
No branch/Via matching, no RFC 3261 timers (only a hardcoded 5s INVITE wait vs the 32s
Timer B), **no retransmissions**, and inbound retransmissions are **reprocessed as new
requests** — a duplicated UDP INVITE re-runs `CreateDialog`/`UpsertCall` and re-fires
group notifications (sip.go:687). No forking (a second 2xx is dropped with no ACK/BYE,
sip.go:208). CSeq is stored but never compared, so no replay/out-of-order rejection. This
is the single biggest structural gap for interop with a real RFSS or S-CSCF.

### 3.5 Unbounded-input DoS on SIP
`readSIPMessage` reads headers with no size cap and then `make([]byte, cl)` for an
attacker-declared `Content-Length` (sip.go:2036) — single-packet memory exhaustion.
`handleTCPConn` sets no read/idle deadline (sip.go:146). `ListenUDP` spawns an unbounded
goroutine per datagram (sip.go:114). The `learned` routes map is populated from any
unauthenticated request and never evicted (sip.go:259), driving an ever-growing 30s
OPTIONS ping loop — a reflection/amplification primitive.

### 3.6 Store has no transactions — real races
No `BeginTx` anywhere. **Two concurrent floor requests from different SSRCs can both pass
`floorCanGrant` and both be granted** (read-evaluate-blind-`UPDATE`, observer.go:123 →
db.go:1141), because there is no `WHERE floor_holder = ?` guard and no version column.
Same read-modify-write class on RTP stats (db.go:1122). On SQLite this is partly masked by
`SetMaxOpenConns(1)`; on Postgres (no connection limit set at all) it is fully exposed.

## 4. High-severity correctness bugs

- **Silent PUT black hole (CMS):** `isGeneratedDocumentAUID` forces GET to always
  regenerate the five MCX documents (cms/server.go:246), but `put` has no matching guard.
  A PUT to `org.3gpp.mcptt.user-profile` returns 201/204 with an ETag and persists — then
  is **never served**; GET always returns the generated body. The client believes the
  write succeeded.
- **XCAP has no `If-Match`/`If-None-Match` handling** (cms/server.go:149) — every PUT is
  blind last-writer-wins; RFC 4825 §7.11 mandates `412`. A test actually asserts the
  *wrong* behavior (server_test.go:566-601).
- **XCAP stores unvalidated bytes:** no XML parse, no XSD check at runtime; `Content-Type`
  is echoed verbatim from the request (cms/server.go:135). No body size limit. GET of a
  nonexistent doc returns 200 with a synthesized default instead of 404.
- **Re-INVITE ignores new media (SIP):** in-dialog re-INVITE answers fresh SDP but never
  updates the stored call's media endpoint (sip.go:826), so the RTP relay keeps targeting
  the old port. Compounded in the store: `UpsertCall` never resets floor state on conflict
  (db.go:938), so a re-INVITE inherits a stale floor holder and **all RTP is then dropped**.
- **CANCEL matches on Call-ID alone** (sip.go:794) and unconditionally marks the
  dialog/call terminated even when no dialog exists, returning 200 (should be 481).
- **Floor accounting bugs (media):** SSRC-change reset does not reset the packet counter,
  so loss is permanently pinned to 0 after a talker change (observer.go:391); `rtp_rejected`
  writes `last_rtp_at`, poisoning the jitter arrival delta (db.go:1106); `floorCanGrant`
  returns true when state is `denied` even with a holder set, so after any deny any SSRC
  can seize the floor (observer.go:521).
- **Timestamp comparison bug (store):** timestamps are stored as `RFC3339Nano` TEXT and
  compared lexicographically for expiry (db.go:768, db.go:1353). Go strips trailing zeros,
  so `.5Z` sorts after `.55Z` — sub-second expiry checks are occasionally wrong on both
  SQLite and Postgres.
- **Likely-broken test:** `TestNotifyDialogRoutesReverseRecordRouteSetByDefault`
  (sip_test.go:367) asserts a reversed route set, but `config.Default()` sets
  `NotifyRouteSetOrder = "preserve"`, so the code returns the input unchanged. The default
  was probably flipped without updating the test — worth confirming once Go is installed.

## 5. Test coverage and hygiene

- **`internal/api` has zero tests** — the entire OAM surface and the IdMS shim are
  untested.
- **SIP:** 20 tests, all in-process; they cover parsing and handler happy paths but
  **none of the outbound UAC half** (`sendOutbound`, `sendRXInvite`, `sendRXBYE`,
  group fan-out — the most bug-dense code), no CANCEL/UPDATE/INFO, no socket-level test,
  no `-race`, no malformed/hostile input. Assertions are mostly `strings.Contains`, so
  header-ordering regressions pass silently.
- **Media:** 10 tests, all pure functions, zero I/O — the relay loop, `matchCall`, and
  `updateJitter` are never exercised (jitter is never asserted anywhere).
- **Store:** 4 tests, **SQLite only** — the entire Postgres path (`s.q()` rewriting,
  the PG migration branch, `ON CONFLICT`) has zero coverage, as does `UpsertCall`'s ~30
  merge branches and all of registrations/dialogs/subscriptions/CMS-docs.
- **CMS:** 10 tests, weighted to document generation; `put`/`delete` are untested, and the
  XSD validation test `t.Skip`s silently when `xmllint` is absent — on a CI image without
  libxml2 the suite is green with no schema validation performed.
- **No `TODO`/`FIXME`/`HACK` markers exist anywhere** in `internal/` or `cmd/`. Every gap
  above is silent, not flagged.

### Repository hygiene (fix now — cheap and high-value)
- **No `.gitignore`.** The compiled `bin/mcxas` binary and **8,629 `web/node_modules`
  files are committed** to the repo.
- The 172 MB `project-VectorCore-MCX/` tree of copyrighted TIA/ETSI/3GPP spec PDFs is
  present in the working tree (currently untracked) — one accidental `git add .` from
  being committed. It should be moved out of the repo or explicitly ignored.
- **Committed lab data in `config/config.yaml`:** a real internal IP (`10.90.250.54`),
  a **real assigned US PLMN** (MCC 311 / MNC 435 — FirstNet/AT&T band 14, not the
  `001/01` test PLMN), a real-format IMEI (`356938035643809`, also baked into
  `config_test.go`), a subscriber-form identity, and a Postgres DSN with an embedded
  `mcxas:mcxas` password and `sslmode=disable`. The default SQLite DSN is `/tmp/mcxas.db`
  — the whole subscriber database in a world-writable directory.
- **systemd unit runs as root** with no `User=`, no `DynamicUser=`, and none of the
  standard hardening (`ProtectSystem`, `NoNewPrivileges`, etc.), against a binary that
  binds low ports and parses hostile network input.
- **Config has no validation function** — invalid enums, port collisions
  (`rtcp_port`/`floor_control_port`), and a nonexistent `-c` file all pass silently, the
  last booting a fully-default loopback server with no warning (config.go:98).

## 6. P25 ISSI readiness — the specific question

### What ISSI can reuse as-is
- The **low-level SIP parser** (`Parse`, `Parts`, `readSIPMessage`, `buildRequest/Response`,
  `parseSDP`, header helpers) — ~500 of the 2709 SIP lines are protocol-neutral.
- The **RTP relay's opaque-payload forwarding**: `relayRTP` copies bytes verbatim, so
  IMBE/AMBE+2 voice frames (TIA-102.BAHA) relay unchanged, and `rtpClockRate = 8000`
  happens to be correct for IMBE (160 samples / 20 ms), so the jitter math is right by
  accident.

### The real blockers (why it is "not yet")
1. **No peer/domain abstraction.** One concrete `Server`, one identity
   (`cfg.MCX.SIPIdentity`), one realm (`cfg.IMS.Realm`). `handleRaw`'s method switch
   (sip.go:230) has no per-source/per-domain branch.
2. **Content types are hardcoded to MCPTT throughout:** `application/sdp` only,
   `application/vnd.3gpp.mcptt-info+xml` element names (sip.go:2073), `pidf+xml`/
   `xcap-diff+xml` NOTIFY bodies, `poc-settings`/`presence` PUBLISH only.
3. **SDP generation is MCPTT-only:** the answer always appends
   `m=application <port> udp MCPTT` with `mc_priority`/`mc_granted`/`mc_implicit_request`
   (sip.go:1757), and floor state is driven by parsing that string. ISSI's RTP + X-TIA
   attributes and its in-band PTT model have no hook.
4. **Group detection is a substring test:** `groupURIFromInvite` decides "group call" by
   testing whether the R-URI contains `"group"` (sip.go:1781) — `sip:groupleader@…` is
   misclassified. There is no WACN/System ID/talkgroup model, no home-vs-serving RFSS, no
   SU roaming, no unit-to-unit.
5. **Registration is IMS third-party REGISTER**, gated on the `+g.3gpp.mcptt` feature tag
   (sip.go:403); an ISSI RFSS REGISTER is silently 200'd and discarded.
6. **Media uses one global RTP port for the whole server** (observer.go:57); the per-call
   `local_audio_port` column exists but is dead code. ISSI needs SDP-negotiated per-session
   port pairs toward each peer RFSS.
7. **ISSI carries PTT control in the RTP stream** (same port, distinguished by payload
   type), but the floor state machine is only reachable from the separate `"floor"`
   listener (observer.go:119); the RTP branch only *reads* floor state. The dependency at
   observer.go:95 would need to be inverted.
8. **Floor protocol is MCPTT/24.380-specific and identity is SSRC-only**
   (`floorHolder()` = `ssrc:%08x`, observer.go:566) — no binding to an SU/WGID identity.

### Recommended sequence before writing ISSI code
1. **Security floor first** (§3): add SIP digest auth + trusted-peer config, put a
   config flag on `/idms/*` and stop issuing `alg:none` tokens, add TLS to all listeners,
   add auth to the OAM API and XCAP server, and cap SIP input sizes. None of this is
   ISSI-specific, but ISSI multiplies the attack surface.
2. **Extract two seams:**
   - A **transaction/transport layer** under the SIP dispatch (branch matching, timers,
     retransmission, per-transport send with connection reuse). This is prerequisite to
     any real RFSS interop, MCPTT or ISSI.
   - A **peer-profile interface** — `{ identity, realm, admission policy, body
     encode/decode, media profile, floor protocol }` — so the method handlers stop
     assuming MCPTT. On the media side, a `FloorProtocol{Parse, BuildGrant, BuildDeny,
     BuildIdle, BuildTaken}` + `MediaProfile{Sockets(), Dispatch()}` pair, and a
     `profile` discriminator column on `mcptt_calls`.
3. **Add a transaction boundary in the store** (at minimum wrap floor-grant and
   membership mutations in `BeginTx` with guarded `WHERE` clauses) and **add the missing
   indexes** — there are currently **no indexes at all**, and every media packet does a
   full-table scan of `mcptt_calls`.
4. **Then** add ISSI as a profile: RFSS REGISTER/heartbeat, SU/WGID identity model,
   ISSI SDP + in-band PTT, and per-session media ports.

Estimated blast radius for the abstraction work, before any ISSI logic: all of
`observer.go`, `store.FloorStateUpdate`, the `media.Store` interface, one new schema
column, and a structural refactor of the SIP handler layer.

---

## 7. One-line answer

Solid MCPTT lab prototype with genuine breadth, but it is unauthenticated top to bottom,
has no SIP transaction layer, no store transactions, and no peer abstraction — so it is a
good base to *build on* but not yet ready to *bolt ISSI onto*. Do the security floor and
the two abstraction seams first; ISSI then becomes a profile rather than a fork.
